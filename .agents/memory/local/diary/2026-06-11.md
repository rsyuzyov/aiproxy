## ProxyBridge — ДОКАЗАНО причина зависания всех локальных панелей (A/B на ct 107)

- Юзер дал чистое наблюдение: внешка (google, ifconfig.me) работает, а все 3
  локальные панели (cliproxy 8317, 9router 20128, OmniRoute 20129) не открываются.
- A/B через curl из контейнера:
  - **Phase A (ProxyBridge вкл):** google/ifconfig 200 (exit IP 72.56.181.101=прокси);
    все 3 панели — timeout 12с (000 / частичный 200 с висящим телом).
  - **Phase B (ProxyBridge выкл, `--cleanup`):** все 3 панели — **200 за 0.002–0.027с**;
    exit IP стал реальным (195.178.4.135).
- **Вывод:** общая причина — перехват ProxyBridge (NFQUEUE на OUTPUT), а НЕ баги в трёх
  разных бинарях. Апрельский вывод «у каждого свой баг в HTTP-хендлере» — **опровергнут**.
  9router «eventfd deadlock» из апреля — скорее всего тот же эффект.
- Механизм (рабочая версия, не добит): loopback в правилах = DIRECT, но пакеты всё равно
  идут через userspace NFQUEUE; либо ломается реинъекция loopback, либо серверный рендер
  панелей делает исходящий self-fetch (по hostname/реальному IP), который ловит `*:PROXY` →
  внешний SOCKS5 → виснет. Точную причину пинить strace/ss на процессе панели во время висяка.
- ProxyBridge V4.0-Beta: спец-флага «не трогать loopback» нет (--proxy/--rule/--dns-via-proxy/
  --verbose/--cleanup). Фикс — через правила (DIRECT для self/private) или iptables-исключение `lo`.
- Состояние возвращено: ProxyBridge поднят как **systemd-демон** (GUI убит в ходе теста),
  exit IP снова прокси. Юзер при желании сам запустит ProxyBridgeGUI из LXQt.
- ⚠️ Грабля: `pkill -9 -f gui-wrapper.sh` через ssh совпал с СОБСТВЕННОЙ командной строкой и
  убил шелл (exit 137). Убивать ProxyBridge-процессы только **по PID**, не `pkill -f`.

## ProxyBridge — уточнение механизма + провал ручного фикса

- Полная команда ProxyBridge (pgrep -af): правила `*:127.0.0.1:*:BOTH:DIRECT`,
  `*:192.168.88.*:*:BOTH:DIRECT`, `*:go.senthy.com:*:BOTH:DIRECT`, `*:*:*:BOTH:PROXY`,
  `--dns-via-proxy true`, прокси socks5://72.56.181.101:8000 (с кредами — в память не пишу).
- `ss` во время висяка: соединение панели = `[::ffff:127.0.0.1]:8317` (dual-stack/IPv4-mapped).
  Гипотеза: mapped-форма не матчит `127.0.0.1:DIRECT` → попадает в `*:PROXY` → loopback гонится
  через внешний SOCKS5 → не возвращается → 000.
- Пробовал фикс `iptables -I OUTPUT 1 -o lo -j ACCEPT`: панели чинятся, НО внешка уходит
  напрямую (exit IP стал реальный 195.178.4.x) — ProxyBridge **сломался от правки цепочки и снял
  NFQUEUE**. Точечное `-m multiport --ports 8317,20128,20129` — то же (PB уже в сломанном состоянии).
  **Вывод: ручная правка iptables при живом ProxyBridge не годится** (он реагирует снятием перехвата).
- Очистил правки, `systemctl restart proxybridge` → baseline восстановлен (exit=прокси, панель висит).
- Дальше фикс искать через: bind панелей на IPv4-only, либо правила ProxyBridge под mapped/`::1`,
  либо upstream-репорт (V4.0-Beta). strace в LXC не цепляется (ptrace закрыт) — диагностика через ss.
